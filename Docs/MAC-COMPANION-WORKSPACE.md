# Mac Companion workspace

The existing iOS app selects the workspace when `ProcessInfo.processInfo.isiOSAppOnMac` is true. This is the Designed for iPad app on Apple silicon, not a new macOS or Catalyst target. Ordinary iPhone and iPad launches retain the existing companion interface.

During gameplay, the game fills the available height beside a collapsible right sidebar. There is no left navigation rail, top toolbar, or bottom status bar. Floating controls at the top right provide the workspace actions menu and sidebar toggle. Library opens the existing game chooser; Game menu opens the existing pause, save-state, and fast-forward controls. Friends and Settings use the existing screens, with explicit pause/resume handling for direct presentation from the workspace.

Mac and both iPhone UI versions share the current Friends and account layout. Friends places Add beside the Friends list heading, above the secondary multiplayer controls. Both Friends and Settings → Account & Sync open Account and Security for username, email, password recovery and authenticator controls. Passkey controls are hidden on every platform. The shared Settings switch is labeled Enable Experimental Multiplayer. Account controls remain available with multiplayer disabled. The saved iPhone UI Version is preserved.

The sidebar has three independent regions: Friend video at the top, Dex/Docs in the middle, and Notes/Types at the bottom. Friend video fills its region above a single Connect/Disconnect button, without the previous heading or card frame. The handle on the sidebar's left edge changes its width while reserving usable gameplay space. A second handle between Friend and the middle region redistributes their height. The bottom region scales with the window height. Hiding the sidebar gives its space back to gameplay and preserves the selected content and pane sizes for reopening.

The workspace menu includes Friend Gameplay and Multiview visibility switches for mouse and trackpad use. Each hides or restores its own region while preserving the other region, reference selections, and divider position. Hiding Friend gameplay keeps its sharing connection active, matching the existing controller visibility actions.

Dex and Docs use the same `BoundRRDexView` and `BoundBossGuideView` as iPhone, with their existing catalogs, per-game selections, separate saved layouts, and UI Version setting. Visited middle references retain their learnset/tab choices and scroll positions using the same retained-view wrapper as iPhone; hidden references cannot receive taps or refresh the game save. Choosing Notes or Types in the bottom region leaves the middle reference mounted and visible. The references are hosted at normal size without the floating-PiP scaler or Dynamic Island inset. There is no separate Mac dataset or extra reference information. Notes and the type chart also reuse their existing views. The Mac type chart fits and centers the entire image inside its own viewport at the minimum zoom, adapts when that viewport resizes, and retains zoom and pan controls. The existing iPhone chart layout remains unchanged.

The coordinator continues to own one `FriendSharingSession`. Its remote view is mounted only once, and remote presentation stays enabled when a reference tab is selected. Account, transport, frame publication, backend schema, save synchronization, and emulator-core sources are unchanged. The desktop uses Delta's existing touch-only controller skin so keyboard/controller input and DS touchscreen input retain their normal receivers.

## Integration with the iPhone interface

Most workspace UI code lives in `BoundMacWorkspaceView.swift` and `BoundMacWorkspaceGeometry.swift`. Integration touches the companion coordinator, game view controller, and Xcode source membership. The ordinary iPhone/iPad branch keeps its independent button-view memory, retained Boss/Dex tab and scroll state, and portrait game/controller geometry. Both interfaces share the current reference views and Settings, including Rules & contact under About.

Settings → Controls also shares Controller Mode, Allow Controller to Control Multiview, and the Controllers mapping editor with iPhone. Controller Mode enables assigned companion navigation actions in the Mac inspector. Allow Controller to Control Multiview additionally routes the controller's D-pad, A/B, and right stick to the visible reference; the existing default LT/RT bindings switch tabs. Custom mappings keep the same precedence as on iPhone. Mac routing works in both wide and tall windows and is independent of the saved iPhone screen layout.

Automatic Multiview capture applies to gamepads. Keyboard gameplay remains available, and explicitly mapped keyboard companion shortcuts still work.

Previous/Next Multiview Tab wraps through Dex, Docs, Notes, and Types, moving controller focus while retaining the other region's independent selection. Explicit reference shortcuts also reopen the sidebar. Friend and Multiview toggle/hide bindings control the corresponding sidebar regions; hiding Multiview returns input to gameplay. The sidebar offers Show Friend Gameplay and Show Multiview buttons, and selecting a reference tab also reveals it. Changing reference tabs keeps Friend video visible unless explicitly hidden. Reference dialogs still close before a controller switches or hides their tab.

## Mac Metal cache startup workaround

Native Mac crash reports showed `RUNNINGBOARD` / `0xDEAD10CC` termination when the app was suspended while Metal held `archiveUsage.db/lock.mdb` outside the permitted container paths. Before `UIApplicationMain`, `BoundMacMetalCache` redirects the app-specific `com.apple.metal` directory beneath Darwin's user cache directory to `Library/Caches/BoundMacMetal/com.apple.metal` inside the app container. It uses public filesystem APIs and runs only when `isiOSAppOnMac` is true; the Simulator workspace override does not enable it. The renderer and upstream cores are unchanged.

Migration preserves complete cache directories. If the destination already exists, the previous cache is retained separately as `com.apple.metal.previous-<UUID>`. Unexpected files or symbolic links are rejected, and failed link creation attempts to restore the original directory. Setup failures are logged under `MacMetalCache`, then normal startup continues. `MacMetalCacheTests` covers migration, repeat setup, preservation, path rejection, and rollback.

For an isolated QA build, override `BOUND_APP_BUNDLE_IDENTIFIER` with a dedicated identifier using compatible signing settings. Only the app target derives its `PRODUCT_BUNDLE_IDENTIFIER` from this setting; the default remains `com.evanvonessen.bound`, and dependency bundle identities remain unchanged. Install through Xcode's Designed-for-iPad destination and run without a debugger. Validate the actual cache file paths, RunningBoard suspension, and foreground recovery with the same process ID; merely switching windows or exercising the Simulator layout is insufficient.
