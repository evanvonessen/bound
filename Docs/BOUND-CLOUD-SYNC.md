# Bound cloud sync

Bound exposes Delta’s existing Harmony sync flow in Settings → Account & Sync. Sign into your **Bound account**, open **Cloud Sync → Delta Sync**, enable Dropbox, then choose **Connect Dropbox**. An existing Bound-linked Dropbox connection is restored without another Dropbox consent flow. Otherwise the user explicitly authorizes linking Dropbox once. The same screen contains sync status, device disconnect and account-wide unlink controls. Google Drive is not offered in Bound's sync settings; its pinned Harmony backend remains in the source for compatibility.

Dropbox sign-in requires the Bound-owned `BOUND_DROPBOX_APP_KEY` build setting and a Bound-owned **Full Dropbox** app. Bound sync never uses Delta's bundled OAuth credentials. The older Google client configuration is not used by Bound's sync. If an installation has a saved Google Drive selection, Bound preserves that preference but ignores it for sync and does not start Google Drive; sync stays inactive until Dropbox is selected. Dropbox’s SDK is configured only once per app process; changing account or provider state does not reset or reinitialize it.

Sync uses the existing Delta provider integration and account storage. It synchronizes ROM files, library metadata and artwork, battery saves, and eligible manual save states. Dropbox uses the Delta Emulator folder. Full Dropbox authorization permits broader access even though the integration uses that folder.

The app-owned Dropbox OAuth bridge uses PKCE with offline access. The new `bound-dropbox` backend exchanges authorization codes, encrypts refresh tokens per Bound owner with AES-256-GCM, and returns only short-lived access tokens to authenticated devices. Native-only credentials are never silently migrated. **Bound Cloud Sync** is the configured Full Dropbox app (`qky6pxxx8ks3d2k`), with native redirect `db-qky6pxxx8ks3d2k://2/token`. The public app key belongs in the build setting; the app secret is unused. Required scopes remain `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read` and `files.content.write`.

**Server keys and real account-linked syncing were verified on 2026-10-21.** After the user saved the app key and encryption key securely in Supabase, a credential-free live POST returned the expected `401 unauthorized` instead of `503 not_configured`. Native Dropbox consent/PKCE linking then passed on A. Two independent native simulator installations signed into the same Bound account passed a generated ROM and 128 KiB save round trip: B restored both without another Dropbox consent, uploaded a changed save, and A restored the changed bytes exactly. Silent reconnect and signed-out rejection passed on both, and the generated QA folder was removed. The account link remains available. Evidence and limits are in the [backend setup and verification record](../Backend/dropbox-link/README.md#live-validation--october-21-2026). No secret values were read or committed. Physical phones, independent networks and public Dropbox availability remain unverified.

The app now identifies missing service setup separately from sign-in, rate limits and two-factor requirements. Temporary broker/network failures preserve Harmony's sync history for retry. A cached Dropbox account is shown as connected only after authentication succeeds, so **Connect Dropbox** remains available after an outage. Deauthentication refreshes the provider hook for a later attempt while rejecting callbacks from its previous generation. Successful connection starts sync immediately.

**Disconnect This Device** or disabling sync clears local authorization and retains the Bound account link. **Unlink Dropbox Everywhere** removes the stored grant and attempts Dropbox revocation; already-issued access tokens or accepted remote writes may outlive this action. Bound sign-out pauses sync on this device, cancels authorization and drains old sync before another account can authenticate. Re-enable sync after signing in again; the Bound account link is retained. Cold starts and account switches reset Harmony metadata when the Bound owner changes. Local games and saves remain shared by the installation; enabling sync under another account can upload that local library. Per-device sync preferences are retained.

Full Dropbox access is required because Harmony uses file-property templates. Dropbox's [current endpoint documentation](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/file-properties/templates-list-for-user) excludes App Folder apps; this restriction was also confirmed by a live test. The earlier App Folder test app is unused. **Bound Cloud Sync** currently remains in **Development / Only you** mode, so successful developer-account testing does not establish availability for other Dropbox users or production approval.

On 2026-10-22, native sign-in reproduced Dropbox's **“This app has reached its user limit”** page after login. This refusal happens at Dropbox before the native callback or backend link request. The app owner must open **Bound Cloud Sync** in the [Dropbox App Console](https://www.dropbox.com/developers/apps) and review **Development users**. Dropbox's [App Console guide](https://docs.dropboxapi.com/dropbox-api/docs/get-started/tutorial/app-console#development-users) documents **Enable additional users** for limited testing/internal use. The browser account available during diagnosis showed **No apps yet**, and opening Bound's app directly returned **Only the app's owner can edit the app**. The developer-user setting and a successful retry remain unverified. This shared app registration does not select a shared storage account: each verified Bound user links their own Dropbox, and devices signed into the same Bound account reuse that user's encrypted grant.

Bound cancels pending OAuth and Dropbox account/folder/template validation when the user cancels, fences late callbacks, and cancels active synchronization. Cancellation is best-effort for HTTP requests already received by Dropbox; it cannot roll back a completed remote write. A saved Google Drive selection remains untouched but inactive until Dropbox is selected. Use the **Syncing** switch inside Delta Sync if you intend to disable the provider or sign out, and heed its conflict warning before doing so.
