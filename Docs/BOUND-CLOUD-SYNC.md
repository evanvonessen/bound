# Bound cloud sync

Bound exposes Delta’s existing Harmony sync flow in Settings → Account & Sync. Open **Cloud Sync → Delta Sync**, choose Dropbox, then sign in. The same screen contains sync status and sign-out controls. Google Drive is not offered in Bound's sync settings; its pinned Harmony backend remains in the source for compatibility.

Dropbox sign-in requires the Bound-owned `BOUND_DROPBOX_APP_KEY` build setting and a Bound-owned **Full Dropbox** app. Bound sync never uses Delta's bundled OAuth credentials. The older Google client configuration is not used by Bound's sync. If an installation has a saved Google Drive selection, Bound preserves that preference but ignores it for sync and does not start Google Drive; sync stays inactive until Dropbox is selected. Dropbox’s SDK is configured only once per app process; changing account or provider state does not reset or reinitialize it.

Sync uses the existing Delta provider integration and account storage. It synchronizes ROM files, library metadata and artwork, battery saves, and eligible manual save states. Dropbox uses the Delta Emulator folder. Full Dropbox authorization permits broader access even though the integration uses that folder.

The app-owned Dropbox OAuth bridge requests offline access using PKCE and stores only the refresh credential in device-only Keychain. **Bound Cloud Sync** is the configured Full Dropbox app (`qky6pxxx8ks3d2k`), with native redirect `db-qky6pxxx8ks3d2k://2/token`. The public app key belongs in the build setting; the app secret is unused. Harmony's existing expired-token retry invokes this provider to refresh and retry a failed operation. Explicit sign-out clears Bound's credential; cancellation stops authorization while retaining it. Required scopes are `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read` and `files.content.write`.

Full Dropbox access is required because Harmony uses file-property templates. Dropbox's [current endpoint documentation](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/file-properties/templates-list-for-user) excludes App Folder apps; this restriction was also confirmed by a live test. The earlier App Folder test app is unused. **Bound Cloud Sync** currently remains in **Development / Only you** mode, so successful developer-account testing does not establish availability for other Dropbox users or production approval.

Bound cancels pending OAuth and Dropbox account/folder/template validation when the user cancels, fences late callbacks, and cancels active synchronization. Cancellation is best-effort for HTTP requests already received by Dropbox; it cannot roll back a completed remote write. A saved Google Drive selection remains untouched but inactive until Dropbox is selected. Use the **Syncing** switch inside Delta Sync if you intend to disable the provider or sign out, and heed its conflict warning before doing so.

Historical validation on 2026-10-15, against the then-old opt-in settings UI:

- The unsigned Release iPhone build passed with Dropbox configured and Google hidden. The Settings UI test passed for that build's settings structure, Dropbox's provider row, and the absence of any Google Drive option. This evidence predates the shared Settings home and does not validate its current UI.
- Browser PKCE authorization and offline token exchange succeeded with the authorized Dropbox developer account. All six selected native checks passed, including repeated background token refresh and Harmony account/folder/template validation, a generated 16 KiB upload/download byte comparison and deletion, Harmony sync of a unique synthetic ROM and 128 KiB battery save, deletion sync for both records, and local sign-out/Keychain cleanup. Evidence: `.build/provider-sync-validation/dropbox-full-single-sdk.xcresult`.
- The one-use QA credential file was consumed and removed before the native request. The temporary loopback redirect was removed from the Dropbox console. The initial native `ASWebAuthenticationSession` user flow has not been exercised; the initial grant used browser authorization and a one-use local relay, followed by native refresh/API validation.
- The hosted integration-test target overrides inherited app pod linker flags so Harmony and SwiftyDropbox resolve to the host app instead of loading duplicate static implementations. The successful live run emitted no duplicate-class warnings.
- Google sign-in and sync are not exposed by Bound and were not tested. Public Dropbox availability, cross-device save restore, and physical-device sync remain unverified.

`BoundDropboxOAuthTests.testLiveDropboxPKCERefreshAndHarmonyFolderValidation` is an opt-in live test for an owned QA simulator. It requires a configured Dropbox key, and a private one-use refresh-credential fixture in that app's caches. It otherwise skips. After provider setup, it validates native refresh/account/template setup, a generated byte round trip, Harmony sync of a synthetic ROM and battery save, remote fixture deletion, and local sign-out cleanup. No credentials belong in source, test arguments, or build logs.
