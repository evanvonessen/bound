# Bound on Delta: development prototype

This is an isolated fork of official Delta, with a companion panel for internet friend video, local per-game notes, and the Pokémon type chart. The original Bound checkout and history are untouched. Existing Bound saves, cloud-save protocols and other app features are not migrated.

Baseline: Delta `c1d3d068e019e6493eed45654569db3cc5beb86a`; DeltaCore `633dfa86967816315fe19b482511dab1ce517f28`; GBADeltaCore `869c34aeca9dd2b3fbd329092bb2743b0ae80c98`; VBA-M `453fa0decf179360926fb417725a794aa496d6e3`. GBA native core, scheduling, audio, input and fast-forward code are unchanged. GBA uses Delta's existing Metal bitmap renderer because its OpenGL path crashed in Simulator during keyboard-driven resize/resume.

## Standalone app build

Open **Bound.xcodeproj**, select **Bound** and Run (preparation is optional for ordinary builds). This is a native Delta app target, with explicit upstream dependency projects. No nested app build or old mGBA source is included. The internal target/module remains Delta to preserve upstream nib and vendored Pod identities. Version **0.5.5 (172)**, display **Bound**. See README for prerequisites and signing.

## Use

The gear includes independent **Screen layout**, appearance, native touch feedback and read-only **Emulation backend** sections. **Classic** is the initial/reset theme; **Minimal** draws simple controls in system light/dark colors while preserving native input mappings and button placement. Button and control-stick feedback both default on, matching the pinned Delta settings. Reset appearance/feedback leaves PiP and placements intact. App version: **0.5.5 (172)**. New installations default to **Bound**, the dual-screen portrait/full-height landscape arrangement. **Classic** lets Delta calculate its original game/controller geometry in both orientations and shows the companion as PiP. Existing saved choices are preserved. Choices persist across relaunch; resetting screen layout restores Bound without changing theme, feedback, button placement or PiP preferences. Appearance/feedback reset does not change the saved screen arrangement.

Import your GBA file through Delta's Library. In **Bound** layout, portrait uses two equal 3:2 screens: friend video above your gameplay, followed by native Delta controls. Bound landscape keeps the main game aspect-fit at full available height, with native Delta controls over it and the companion as a corner PiP. **Classic** preserves native Delta screen geometry; its PiP can be adjusted in either orientation. Choose Friend, Notes or Types from the floating toolbar. Notes persist locally per Delta game identifier; editing pauses playback and Done resumes when appropriate. No notes cloud sync is included.

PiP movement and resize start on the panel: one-finger drag follows the finger and snaps to the nearest clear corner on release, two-finger pinch resizes the whole panel (0.65–1.4), and a horizontal edge swipe hides it. B restores a hidden panel before resuming the Friend/Notes/Types cycle. In landscape, a two-finger vertical drag in the center game area changes Friend or Notes opacity; Types always stays opaque and fits the complete chart. Each panel retains its own corner, scale and opacity. Notes previews accept drag/pinch; a tap opens editing. Native control touches and active text editing are excluded. Rotation/backgrounding cancel unfinished gestures; normal finger release commits the last valid sample. Portrait Types keeps its internal chart zoom/pan.

Open the gear and choose **Buttons** for Bound-style native Delta button placement. Delta is the default and reset choice. Portrait and landscape drafts are saved separately per skin. Drag/select controls, resize from 70–140% in 5% steps, nudge by 8 points, reset selected/all, and Save or Cancel. Customized portrait controls may move throughout the full viewport. Native artwork and hit regions move together; overlapping controls retain Delta input precedence. The companion toolbar stays available above custom controls; Notes/Types remain toolbar toggles rather than emulated inputs. Editing does not activate emulator inputs. Notes editing and rotation cancel held touchscreen input; hardware controller behavior stays native Delta.

Friends uses the existing Bound account/friend backend and the existing Agora 4.6.4 adapter. Sign in through the Friends button, select an existing friend or exchange an invite, and Start sharing. Account sessions are retained in the device-only Keychain and restored silently on later launches. The shared account owner refreshes expiring sessions; offline startup retains the saved login. Revoked sessions require sign-in again. Explicit sign-out removes the saved session and invalidates existing credential holders. Passwords are never retained. Signing out, backgrounding, returning to Library or changing games stops sharing. After a game change, explicitly start sharing again. No friend was contacted during development.

Capture is off when sharing is not joined. Enabled capture samples at most 30 frames/second, retains an immutable already-copied Delta bitmap on the emulator owner, and rasterizes on a utility queue. One frame stays in flight through main delivery; epoch fences prevent stale output after stop/rebind. Only game pixels are shared, not UI/notes. The GBA friend output is 240×160; GPU-backed cores are outside this prototype's capture support.

The Emulation backend section reads the actual selected core's package name, identifier and optional version. For GBA it distinguishes **GBADeltaCore** integration (pinned `869c34aeca9dd2b3fbd329092bb2743b0ae80c98`) from the **VBA-M** engine (pinned `453fa0decf179360926fb417725a794aa496d6e3`). Upstream exposes no wrapper release version, so the UI reports a source revision rather than inventing one. DeltaCore and Delta upstream revisions and the app version/build are also shown. Screen arrangement never switches the engine. Model/hosted checks verify runtime GBA identity and revision constants against the committed pin manifest.

## Verification

`PrototypeTools/verify.sh` runs preparation, the model suite, hosted offline integration/benchmark, Simulator UI checks and an unsigned Release iPhone build. It uses the dedicated “Bound Gameplay Pacing QA” Simulator, or `QA_SIMULATOR_ID` if supplied; only that Simulator is booted. Logs are retained under `.build/verification/latest`. `QA_DERIVED_DATA` and `PHONE_DERIVED_DATA` optionally reuse existing build caches. No live RTC engine, account, invite, microphone or camera is involved in offline tests.

**BoundIntegrationQA** runs real native VBA-M gameplay from the generated original cartridge through `BoundDeltaFrameTap`, `FriendSharingSession`, the bounded publishing session, the production outgoing pixel pool, receive mailbox and retained canvas presenter. Its injected loopback replaces Agora encoding/network/decoding; the real I420 converter is separately checked with padded planes. It checks pixel fidelity, changing native frames reaching the canvas, a slow send, reconnect, background/stop fencing, stale receive conversion and malformed presentation input. The benchmark repeats all panel/capture combinations in opposite orders, six seconds per sample. Callback timings are native update callbacks, not measured phone scanout or a codec/network benchmark.

`swift test --package-path PrototypeTests` tests actual source files through symlinks, with no network/authentication. The existing Bound Sharing package's aggregate tests cover the copied bounded sharing engine.

The **BoundCompanionQA** scheme exercises persisted Delta Default/Bound selection, native geometry restoration, rotation/relaunch and independent reset, backend provenance, native-layout PiP/Notes/Types, both orientations, equal 3:2 portrait screens, full-height landscape game pixels, PiP drag/pinch, transparency persistence, button-placement save/reset/orientation isolation, the three panels, keyboard/Done, local notes persistence across relaunch, inert sign-in controls, foregrounding while editing, and rotation. Its Debug-only layout arguments isolate the test container: `--bound-ui-screen-layout-bound` explicitly selects Bound for legacy cases and `--bound-ui-reset-screen-layout` removes only the new screen-layout key for the native-default case. These overrides are absent from Release. Its Debug-only `--bound-ui-friend-fixture` launch argument presents original generated RGB pixels through the production remote canvas without using accounts, RTC or the network; Release contains no fixture path. Import the generated original cartridge into the QA Simulator before that test; no personal ROM is needed:

```
python3 PrototypeTools/generate_diagnostic.py .build/fixtures/BoundDiagnostic.gba
xcrun simctl openurl <qa-simulator-id> file://<absolute-path-to-generated-fixture>
```
